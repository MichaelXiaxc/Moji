# Moji 墨迹 · GRBL 写字工作台

用于 ESP32 三轴写字机器人的本地上位机，支持轴点动、步数标定、照片叠加、文字/SVG 排版与 G-code 串口发送。当前设备使用 Grbl_ESP32 1.3a。

## 安装与启动

1. 安装 Node.js 22.12 或更新的兼容版本（本项目使用 Node.js 22）。
2. 在项目目录打开 PowerShell，首次运行：

   ```powershell
   npm install
   npm run dev
   ```

3. 使用桌面 **Microsoft Edge** 打开终端显示的地址，通常为 [http://127.0.0.1:5173/](http://127.0.0.1:5173/)。保持终端运行；按 Ctrl+C 可停止服务。

以后启动只需运行 `npm run dev`。推荐使用已实测连接成功的 Edge。

## 连接与定位

1. USB 连接 ESP32，关闭其他占用串口的监视器或烧录软件。
2. 在网页选择 **115200**，点击“连接串口”，选择 **USB-SERIAL CH340（当前设备为 COM5）**。重新插拔后端口号可能变化。
3. 等待状态显示 `Idle`。用点动按钮移动各轴；默认每次仅 0.1 mm，X/Y 可按需要调大，Z 建议以小距离调整。
4. 若需手动移笔，空闲时点击“电机断电 / 休眠”，等待显示已休眠后移动。完成后点击“唤醒电机”；若出现 Alarm，检查后点击“解除报警锁定”。
5. 将笔定位到纸面左上角，点击“当前位置设为纸面左上角 (X0 Y0)”。再将笔尖轻触纸面，点击“当前位置设为落笔面 (Z0)”。XY 与 Z 分别设置。

坐标约定：**纸面左上角为 (0,0)，X+ 向右，Y+ 向下，Z+ 落笔，Z− 抬笔。**

以纸面为 Z0 时，落笔值通常为 0，抬笔值为负数。默认抬笔 -3 mm 需根据实际机构调整。休眠通过 `$SLP` 关闭驱动使能，不切断整机电源；手动移动后需重新设置零点。

## 排版与书写

1. 设置工作区实际宽、高（毫米），以及抬笔/落笔 Z、书写速度和 Z 速度。
2. **文字**：载入包含所需字符的 TTF/OTF 字体，输入文字或导入 UTF-8 TXT，设置字号、行间距、每行字数、最大行数和对齐，然后添加文字路径。修改文字格式后需重新添加路径。
3. **图形**：导入 SVG；选中图层后拖动，或输入 X/Y、缩放倍数、旋转角度并应用。
4. **照片（可选）**：展开“照片叠加与标定”，分别导入底板和放纸照片。选择照片进行四点校准，按左上→右上→右下→左下点击已知工作矩形的角点；矩形真实尺寸对应工作区宽高。通过透明度叠加检查排版。
5. 点击“生成 G-code”，检查路径和参数。确认原点、轴方向、Z 高度后勾选确认，再点击“开始”；也可导出 G-code。

生成的程序先移动到**绝对抬笔 Z 高度**，再移动到路径起点；每段按“落笔→书写→抬笔”执行。结束后保持抬笔，停在最后终点，不自动回原点。进度表示指令已被控制器接收，实际完成应等待 `Idle`。

“保存工程”可保存路径、照片和运笔参数，下次通过“打开工程”恢复；串口连接和校准确认不保存。照片与字体不上传服务器。

## 标定与常见问题

- **移动距离不准**：串口发送 `$$` 读取参数。X/Y/Z 的 steps/mm 分别为 `$100/$101/$102`；在“步数标定”中输入原值、命令距离和实测距离，计算后写入。公式：新值 = 原值 × 命令距离 ÷ 实测距离。
- **串口打不开**：确认选择正确的 USB 串口，并关闭其他占用端口的软件或网页；查看页面串口错误提示，必要时拔插 USB 重试。
- **点动看不明显**：默认距离仅 0.1 mm，先检查坐标是否变化，再适当调整距离。
- **文字像双线描边**：普通字体生成字形轮廓，不是单线手写或按笔顺书写；不支持 TTC 字体集合。
- **SVG 内容缺失**：支持路径、基础形状和组变换；文字、图片、use 引用、裁剪和蒙版等需先在矢量编辑器中转路径、展开并简化。

暂停后可继续；“停止”和“急停”发送软复位并取消发送队列，之后需重新确认机器状态及坐标。软件急停不能替代硬件急停。旧版左下原点的 G-code 请重新生成。

## 开发命令

```powershell
npm test          # 路径生成、串口逻辑测试
npm run build     # 构建到 dist
npm run preview   # 本地预览构建结果，地址见终端
```
